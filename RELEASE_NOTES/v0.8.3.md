# OpenPencil v0.8.3 — Design Together, Present Anywhere

`v0.8.3` turns OpenPencil from a single-seat editor into a shared one. Real-time
collaboration arrives end to end — authenticated peer-to-peer sessions, a public
relay for peers that cannot reach each other directly, and built-in regional
hubs — alongside browser device login and an online multi-tenant web mode
authenticated against the op-hub.

The release also grows a full presentation-deck workflow (templates, a live
slideshow presenter, and PDF / HTML / PowerPoint / video export), a scene
template center for starting from a real layout, and an official Chrome
web-capture extension that snapshots any page into OpenPencil. Under the hood the
web bundle gets lighter by fetching templates, the icon catalog, and preview art
at runtime instead of embedding them, and theme becomes a per-device preference.

## Highlights

- **Real-time collaboration** — authenticated P2P sessions with a public relay
  fallback and built-in regional hubs. Join with a 10-character, region-tagged
  pairing code; see live remote cursors; resolve conflicts with per-edit detail
  and replay of discarded edits. Cross-account collaboration is supported.
- **Online multi-tenant web mode** — the `--serve-web` daemon can host multiple
  tenants, authenticated against the op-hub, with cross-account tenant sharing
  and eviction persistence. The online `/mcp` surface enforces capability
  profiles and scope.
- **Device login** — sign in from the browser through the serve-web daemon, with
  a runtime account gate and authenticated profile avatars and usernames in the
  editor.
- **Presentation decks** — six 16:9 deck templates and a template picker, AI deck
  planning at projector size (one slide per screen), a slideshow presenter, and
  export to PDF, self-contained slideshow HTML, editable PowerPoint (`.pptx`),
  and a hyperframes video composition.
- **Scene template center** — a browsable catalogue of 58 templates across six
  scenes, opened from File ▸ New from template and available in the browser host.
- **Chrome web-capture extension** — snapshot any webpage into OpenPencil with
  faithful HTML, icon, and layout capture, delivered to your account's snapshot
  inbox on the hub, or downloaded as a ready-to-open `.op` file offline.
- **Lighter web bundle** — scene templates, the icon catalog, and preview assets
  are fetched at runtime instead of being embedded in the wasm bundle.
- **Theme is now a device preference** on the web host.

## Real-Time Collaboration

- Authenticated peer-to-peer collaboration is the foundation: peers establish an
  encrypted session, and every accepted participant passes an admission policy
  before any document edits flow.
- A public relay carries traffic for peers that cannot open a direct connection,
  and the client tolerates public-relay handshake latency and reports join
  failure by stage instead of failing opaquely.
- Built-in regional collaboration hubs give sessions a nearby meeting point;
  sessions are joined with a 10-character, region-tagged pairing code that
  replaces earlier open invites.
- Remote participants are painted with live cursors (using the agent pointer),
  and their avatars are proxied through the daemon rather than fetched directly
  by the browser.
- A conflict panel surfaces per-node, per-field detail and can replay edits that
  were discarded during a divergence, so nothing is silently lost.
- Cross-account collaboration lets people signed in to different accounts work in
  the same session.
- Extensive hardening this cycle: resource-exhaustion guards, gesture-capture
  ordering so queued actions wait for a gesture's capture to close, whole-second
  keepalive clamping, secure-relay transport-failure classification, and safe
  rotation of production trust roots.

## Accounts, Device Login, and Online Hosting

- Browser device login runs through the serve-web daemon: a runtime account gate
  governs access, and the editor shows the authenticated profile avatar and
  username once signed in.
- Prebuilt `op-auth` libraries ship for Intel and Apple-silicon macOS, Linux, and
  Windows (MSVC and arm64), so the desktop build links the auth bridge without a
  separate toolchain.
- Online multi-tenant mode lets one `--serve-web` deployment host many tenants,
  authenticated against the op-hub, with cross-account tenant sharing that
  persists across evictions and session-safe recovery for the browser host.
- The online `/mcp` surface authenticates the live endpoint and enforces a
  capability profile and scope, so a hosted MCP client only sees what it is
  allowed to.

## Presentation Decks

- Start from one of six 16:9 deck templates via the template picker, or let the
  AI plan a deck at projector size with one slide per screen.
- Present a deck as a slideshow with presenter controls to drive it.
- A slides rail is the deck's single navigator, and multi-board templates wrap
  onto rows on the canvas.
- Export a finished deck as PDF (one page per slide), a self-contained slideshow
  HTML file, an editable PowerPoint (`.pptx`), or a hyperframes video
  composition.
- The design agent now judges a deck board by its geometry as well as its
  prompt — pinning boards to the projector aspect, centering board content
  instead of stacking it at the top, and reporting row overflow instead of
  clipping it.

## Templates, Prompt Center, and Asset Center

- The scene template center is a browsable catalogue that grew to 58 templates
  across six scenes, opened from File ▸ New from template, mounted in the browser
  host, and fully localized.
- The prompt center gained web, dashboard, component, and modify entries, visual
  prompt previews, and scales with the viewport.
- The asset center grew into a full-window responsive gallery with dual-action
  templates, palette bands, and DESIGN.md style import.

## Chrome Web-Capture Extension and HTML Import

- The official OpenPencil Chrome extension captures a live webpage — settling
  lazy pages before capture — and turns it into OpenPencil design content with
  faithful text, icon, and layout fidelity.
- Captured snapshots are delivered to your account's snapshot inbox on the hub
  (`POST /api/v1/snapshots`); when offline, the extension's download emits a
  ready-to-open `.op` file instead.
- The underlying HTML and browser-snapshot import pipeline was overhauled for
  fidelity: SVG image sources rasterize at the byte-cache seam, inline-flow
  blocks fold into a single styled text node, and web-snapshot text, icon, and
  layout capture are more faithful.

## Web Runtime and Editing

- The web bundle is lighter: scene templates, the icon catalog, and preview
  assets are fetched at runtime rather than embedded, and the web SDK bundle
  tripwire is aligned to the shared budget.
- Theme is now a device-level preference on the web host.
- Drop an image file onto a node to set its fill, and match a node's height to
  its image fill ratio.
- The settings panel was rebuilt as a wide modal with a shared row language; the
  chat panel, slides rail, and template centers were refreshed; documents open
  with top-level layers collapsed, behind a minimized chat bar.
- Complex scripts are now shaped instead of painted in storage order, and IME
  punctuation that commits without a composition is accepted.

## AI and Agents

- One-click MCP registration for twelve CLIs and one-click ACP presets for Kimi,
  Gemini, and Qwen.
- Nine original style guides join the corpus, and the planning corpus learned how
  a projector board differs from a page.
- Documents can record a scenario tag noting what they are for, and quality
  repair passes are tiered, scoped by provenance, and itemized into an
  expandable ledger.
- A prompt asset-generation pipeline and visual prompt previews round out the
  generation experience.

## Release Artifacts and Distribution

- Releases now publish `SHA256SUMS` plus a provenance attestation so downloads
  can be verified.
- The Chrome web-capture extension is prepared for the Chrome Web Store.

## Compatibility Notes

- New panel strings are translated across all fifteen locales.
- CLI and ACP agents remain native-only; the web host continues to expose
  built-in API-key agent profiles only.
- The public web SDK remains read-only.
- The retired TypeScript application (last tagged `v0.7.5`) is not part of this
  release.
